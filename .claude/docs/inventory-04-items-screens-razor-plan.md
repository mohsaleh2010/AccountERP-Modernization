# خطة 04 — شاشات الأصناف (Razor) حسب طبيعة النشاط

تاريخ الإعداد: 2026-10-08. **الحالة: القرارات §4 معتمدة (2026-10-08) — لا تنفيذ بعد.** الأولوية 4 فى [خريطة الطريق](inventory-00-roadmap.md) (يمكن أن تتوازى مع خطة 03).

**النطاق:** قائمة «الأصناف» فى `MainFrm_AccountUpdate`:
- قوائم الأصناف وإضافتها: 11 عنصراً بأشكال مختلفة
- «بيانات الأصناف» و«أصناف النسيج»
- «أسعار الأصناف والمنتجات»
- القوائم المرجعية (فئات، وحدات، أنواع، هيئات، ألوان، وصف، مصانع، مقاسات، فرز، مجموعات، طبيعة)
- الباركود

## 1) الوضع الحالى

### 1.1 الأشكال الموجودة لشاشة الصنف
| الشكل | الشاشة | خصوصيته |
|---|---|---|
| عام (بلاستيك/تجارة) | `Mitems_ListNew` (1584 سطراً)، `Mitems_ListNewNoPrice`، `ItemsListGridFrm`، `ItemsListViewFrm` | وحدتان + أسعار بيع/شراء لكل وحدة |
| سيراميك | `Mitems_List_Sermek` (1669) | مقاسات/فرز/ألوان |
| أدوية | `Mitems_List_PH_R` (1847)، `ItemsListAdwia`، `ItemsListAdwiaRetail` | صلاحية/تشغيلة، بيع بالتجزئة (الشريط) |
| سيارات | `ItemsListCars` (934) | توافق الصنف مع موديلات السيارات (`ItemsForCars`) |
| بالمواصفات (زجاج) | `Mitems_List_WH` (1445، فيه 9 INSERT مباشرة) | أبعاد/مواصفات |
| خدمات بلا رصيد | `Mitems_List_NoBalance` (1769) | `Is_ItemWithoutBalance`، لا حركة مخزن |
| ضريبى | `Connection4It.Mitems_ListTax`، `NewItemCodeList` | كود الصنف فى بوابة الضرائب (`ItemCodeTaxNotUploaded`) |
| نسيج | `Mitems_List`، `ItemDataProduction_ListFRM`، بيانات الوبرة/اللحاف | مواصفات إنتاج (`Item_PriceUnit_List`) |

### 1.2 منطق الحفظ (`ItemCLS.Save_Item`)
- يتحقق من الصلاحية (916 إضافة، 917 تعديل)، ويولّد الكود التلقائى.
- يُدخل `Item` ثم `Unit_item` **بالرصيد المكتوب فى الشاشة مباشرة**.
- يستدعى `SetItem_First_Period_Balance` (صف أول مدة مع كل إضافة).
- **مع `IsAddAllItemInAllStores = 1`:** يُدخل صف `Unit_item` لكل المخازن.
- **مع `IsAddAllItemForAllCars = 1`:** يربط الصنف بكل السيارات.
- **التعديل** (`Save_Item(UnitItemsModelView)`): `UPDATE Unit_item SET Full_qua=…, D_Qua=…` — يغيّر الرصيد من شاشة الصنف.

### 1.3 ما هو مبنى فى Razor فعلاً
- `BarcodePrintSettings` و`BarcodePharmacyStickers`.
- `PurchaseSalePricesPage`.
- حوار إضافة الصنف داخل الفاتورة `AddInvoiceItemDialog`.
- لا توجد شاشة صنف كاملة.

## 2) التصميم المقترح

### 2.1 شاشة صنف واحدة بملفات نشاط (Profiles)
**قرارك (2026-10-08): الاثنان معاً بمكوّن واحد** — لا تكرار للمنطق:
1. **الشاشة الموحَّدة** `/items/{Id?}` فى **عنصر قائمة جديد** «الأصناف (الشاشة الموحَّدة)»: الأقسام تظهر حسب **ملف النشاط** المأخوذ من فئة الصنف (أو الافتراضى العام).
2. **شاشة لكل شكل** `/items/p/{profile}/{Id?}` (عام، خدمات، أدوية، أدوية تجزئة، سيارات، سيراميك، زجاج/مواصفات، ضريبى، نسيج): **نفس المكوّن** بملف نشاط ثابت، وتُربط بها عناصر القائمة الحالية المقابلة (`menuItemItemsListSpecAdwia`، `menuItemItemsListSpecCars`، `menuItemItemsListSpecSeramek`، `menuItemItemsListNoBalance`، `menuItemItemsList`…).

| القسم | يظهر فى |
|---|---|
| الأساسى: الاسم (عربى/إنجليزى)، الكود، الباركود، الفئة/المجموعة، النوع (صنف/خدمة)، نشط | الكل |
| الوحدات: الكبرى/الصغرى/معامل التحويل/العبوة، الوحدة الافتراضية للبيع والشراء | الكل |
| الأسعار: بيع/شراء لكل وحدة، قوائم الأسعار (`Price_Type_Sell_Values`)، أسعار العملاء والموردين | الكل |
| الضرائب: نسبة، كود البوابة، حالة الرفع | ضريبى |
| الصلاحية والتشغيلة: تتبع إلزامى، أقل صلاحية للبيع، البيع بالشريط | أدوية |
| المواصفات: مقاس، لون، فرز، أبعاد، مصنع، هيئة | سيراميك، زجاج، نسيج |
| التوافق: موديلات السيارات | سيارات |
| المكونات (BOM) | منتجات مصنَّعة (خطة 05) |
| المخازن: المخازن المرتبطة، حد الطلب، **الرصيد للعرض فقط** | الكل عدا الخدمات |

قائمة الأصناف `/items` بشبكة قابلة للفلترة والتصدير، وأعمدتها حسب الملف (بديل `ItemsListGridFrm`/`ItemsListViewFrm`/قوائم الأنشطة).

### 2.2 قواعد الرصيد (توافقاً مع خطة 01)
- **رصيد ابتدائى عند الإضافة فقط (قرارك 2026-10-08):**
  - **متى:** حقل «الرصيد الابتدائى» (كمية بالوحدتين + تكلفة الوحدة) يظهر عند إضافة صنف جديد فقط.
  - **كيف:** يُرحَّل عبر المحرك كرصيد أول المدة للفترة الحالية (خطة 02): صف فى `Item_First_Period_Balance` بالفترة + صف DPIE افتتاحى + تحديث `Unit_item` ومتوسط (صنف × فرع).
  - **بعد الإضافة:** تعديل الصنف لا يغيّر الرصيد إطلاقاً، وأى تغيير لاحق بإذن تسوية أو من شاشة أول المدة.
- إضافة صنف تُنشئ صف `Unit_item` بكمية صفر للمخزن الافتراضى (وللمخازن الأخرى حسب `IsAddAllItemInAllStores`)، وصفوف المخازن الأخرى والسيارات تُنشأ عند أول حركة (المحرك).
- لا يُكتب صف أول مدة تلقائياً مع كل إضافة **إلا** إن أُدخل رصيد ابتدائى (مصدر تضخم `Item_First_Period_Balance` اليوم أنه يُكتب دائماً حتى بالصفر).

### 2.3 القوائم المرجعية والأسعار
- صفحة عامة للقوائم المرجعية البسيطة (اسم + نشط) تخدم ~11 جدولاً (`Items_Types_Name`، `Items_Bodies_Name`، `Items_TypesColor_Name`…) بنفس نمط صفحات «بيانات أساسية» المبنية.
- الوحدات `unit`، الفئات `Item_Main_Category`/`Item_Category`، المجموعات `Items_Group`، الطبيعة `Items_Nature`.
- الأسعار:
  - أنواع أسعار البيع والشراء
  - تصنيف الأسعار وتعديلها الجماعى
  - البحث عن سعر صنف
  - أسعار العملاء (`Customer_Price`) والموردين (`Supplier_Price`)
  - الطباعة

## 3) التعارضات وحلها
| التعارض | الحل |
|---|---|
| إضافة/تعديل الصنف يكتب الرصيد مباشرة | فى Razor: الرصيد الابتدائى عند الإضافة فقط عبر المحرك كأول مدة، والتعديل لا يمس الرصيد (§2.2). الشاشات القديمة تبقى حتى نقل القائمة، والمطابقة (خطة 01) تكشف أثرها |
| `SetItem_First_Period_Balance` مع كل إضافة | لا يُستدعى من Razor؛ أول المدة من خطة 02 فقط |
| `IsAddAllItemInAllStores` ينشئ صفوفاً لكل المخازن | يبقى الإعداد محترماً بكمية صفر؛ والسيارات (خطة 06) تُنشأ صفوفها عند أول تحميل |
| 8 أشكال شاشة بمنطق مكرر (بعضها INSERT مباشر) | شاشة واحدة بملفات نشاط فوق `ItemCLS` (`Save_Item`) بعد فصل جزء الرصيد |
| حقول خاصة بالنسيج (`Item_PriceUnit_List`) | قسم «مواصفات إنتاج النسيج» يُبنى مع خطة 05 (نطاق النسيج معتمد) |

## 4) القرارات (2026-10-08)
| # | القرار | المعتمد |
|---|---|---|
| م-04-1 | شكل الشاشة | **الاثنان بمكوّن واحد:** شاشة موحَّدة بعنصر قائمة جديد + شاشة لكل شكل (نفس المكوّن بملف ثابت) مربوطة بعناصر القائمة الحالية |
| م-04-2 | مصدر ملف النشاط | **لكل فئة صنف + افتراضى عام** |
| م-04-3 | الرصيد من شاشة الصنف | **رصيد ابتدائى عند الإضافة فقط** عبر المحرك كأول مدة؛ التعديل لا يغيّر الرصيد |
| م-04-4 | أولوية الأشكال | **معتمد:** عام ← خدمات ← أدوية ← سيارات ← سيراميك/زجاج ← نسيج |

| م-04-5 | تعديل اسم فى قائمة مرجعية (2026-10-10، حسب الأنظمة الحديثة) | يُحدَّث الاسم المنسوخ فى `Item` أيضاً داخل نفس المعاملة حتى لا تختلف الشاشات القديمة؛ الحذف ممنوع إذا كانت القيمة مستعملة فى أصناف، والإيقاف (IsActive) متاح للطبيعة فقط لأن باقى الجداول بلا عمود حالة |

| م-04-6 | الوحدات (2026-10-10، حسب الأنظمة الحديثة) | عدد الصغرى فى الكبرى يُقفل للوحدة المستعملة (Unit_item يحفظ نسخة منه وتُحسب بها الأرصدة) — التغيير = وحدة جديدة؛ تعديل اسم الكبرى يحدّث Item.UnitStr فقط والمستندات تحتفظ باسمها وقت الإصدار؛ وحدة افتراضية واحدة |
| م-04-7 | الفئات (2026-10-10، حسب الأنظمة الحديثة) | إيقاف الفئة يمنع اختيارها فقط ولا يوقف أصنافها (الشاشة القديمة كانت تضع Active_flage=-1 لكل الأصناف حتى عند إعادة التشغيل)؛ فئة افتراضية واحدة لكل (أصناف/خدمات) ولا تُوقف؛ النوع الرئيسى لا يُحذف وبه فئات؛ معرّف النوع الرئيسى MAX+1 لأن Main_Item_Category_Id من نوع int، والوحدة والفئة Snowflake مثل EF (أو هوية إن كان العمود هوية) |

| م-04-8 | شاشة الصنف (2026-10-10، حسب الأنظمة الحديثة) | (1) الكود التلقائى = أكبر كود رقمى + 1 (من 1000) ولا يتكرر — على ClientNew كان 452 صنفاً بكود «0» لأن `UpdateItemCode` القديمة تحدّث `Item WHERE Id = Code` فلا تطابق شيئاً؛ لم تُصحَّح الأكواد القديمة (قرارك). (2) الأسعار بيانات صنف: تُحفظ على Item وكل أسطر Unit_item. (3) الخدمة = بلا رصيد إجباراً. (4) تغيير الوحدة أو «بلا رصيد» ممنوع لصنف له رصيد أو حركات. (5) إضافة الصنف لمخزن آخر برصيد صفر من الشاشة. (6) الإيقاف يكتب Active_flage = -1 كالقديم |

## 6) الاختبار
- إضافة صنف بلا رصيد ابتدائى: `Item` + `Unit_item` بكمية صفر ولا صف أول مدة؛ وبرصيد ابتدائى: صف أول مدة بالفترة + DPIE + `Unit_item` والمتوسط، الكود التلقائى صحيح، الصلاحية 916 تمنع.
- تعديل صنف لا يغيّر `Full_qua`/`D_Qua`.
- الأقسام تظهر وتختفى حسب ملف النشاط.
