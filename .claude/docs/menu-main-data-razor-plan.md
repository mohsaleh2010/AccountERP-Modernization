# خطة تحويل قائمة "بيانات أساسية" (menuItemMainData) إلى Razor

**الحالة: التنفيذ جارٍ بموافقتك — بالترتيب المقترح فى القسم 3، بدون إصلاح الأخطاء الثلاثة القديمة المكتشفة فى
شاشات الدول/المدن (تُترَك كما هى فى الأصل، وتُوثَّق فقط فى `winforms-porting-checklist.md` إن لم تكن موثَّقة
هناك بالفعل).**

مبنية على بحث مباشر فى الكود الفعلى (وليس افتراضاً) لكل الـ 35 عنصر قائمة تحت `menuItemMainData`، بنفس منهجية
دفعة "الحسابات" السابقة (`.claude/docs/menu-main-account-razor-plan.md`): تتبُّع كل عنصر قائمة → الفورم الحى
الفعلى (بالتحقق من `<Compile Remove>` وملفات `MainFrm_AccountUpdate.cs` مباشرة، لا افتراضاً) → الكلاس/الـCLS
المستخدَم → الجداول → حالة التحويل لـBlazor.

---

## 1) قرارات فورية تحتاج تأكيدك (قبل البدء)

| القرار | التفاصيل |
|---|---|
| **تكرار مؤكَّد**: "تغيير الإعدادات" + "نص بيان الفاتورة" | كلاهما يقرآن/يكتبان **نفس مفتاح الإعداد الوحيد بالضبط** (`Static_NotesInInvoicePrintNotShowCustomerAccount` عبر `Common.Get/Save_SystemParametersDB`) - فورمان مختلفان بحقل نصى واحد لكل منهما، بلا أى فرق وظيفى. **سنبنى صفحة Razor واحدة فقط** تخدم كلا عنصرَى القائمة، ما لم تُخبرنى بخلاف ذلك. |
| **"قيود إفتتاحية سابقة" (menuItemOldKewd)** | الـ`.Click` **معلَّق بالكامل فى الكود الحى** (كل السطور `//`) - **لا يفعل شيئاً عند الضغط عليه فى التطبيق الحالى**. الكلاس الذى كان سيُستدعى موجود فقط فى شجرة `General_Ledger` القديمة غير المُجمَّعة. **التوصية: لا حاجة لأى عمل** - هذا عنصر قائمة معطَّل فعلياً، سيظهر "قيد الإنشاء" تلقائياً (نفس آلية `KnownRoutes` المُستخدَمة سابقاً لعناصر مماثلة). |
| **"بيانات حساب عميل-مورد-مختلط" (Customer_SupplierInfo)** | شاشة **ربط** (وليست عرض أرصدة - تلك مُنجَزة بالفعل) تكتب `Supplier.Ref_Cust_Supplier_Id` مباشرة. **بلا أى كلاس CLS** (SQL خام بالكامل + الملف بترميز غير صحيح/Mojibake). **التوصية: تأجيل** - شاشة نادرة الاستخدام، تحتاج كتابة منطق عمل من الصفر بدل إعادة استخدام موجود، وتفتقر لأى اختبار مرجعى سهل. |
| **طباعة كشف بيانات العملاء/الموردين** (2 عنصرين، تقارير RDLC) | **التوصية: تأجيل** (نفس مبدأ كل شاشات الطباعة المؤجَّلة سابقاً فى دفعة "الحسابات" - لا توجد شاشة طباعة واحدة مبنية فى Blazor حتى الآن فى كامل المشروع). |
| **"تست طباعة الباركود" (dev-only)** | **التوصية: استبعاد نهائى** من هذه الدفعة - أداة تشخيص/اختبار داخلية للمطورين، ليست شاشة عمل. |
| **"إعدادات طباعة الباركود" (PrintItemsBarCodeSettingFor_User)** | مصمِّم ملصقات باركود حى (GDI+، معاينة فورية، طباعة مباشرة، حتى مسار ملف مطلق ثابت `D:\test.bmp`) - **ليست تحويل فورم عادى**، تحتاج تصميماً مختلفاً جذرياً (توليد صورة باركود من الخادم + طباعة/PDF من المتصفح). **التوصية: استبعاد من هذه الدفعة، تُبنى منفصلة لاحقاً إن احتجتها**. |
| **أخطاء حقيقية اكتُشِفت أثناء البحث (فى الأصل، غير مُصلَحة)** | (1) `CountryCLS.Delete`/`Govern_AreaCLS.Delete_ProjectUnites`: فحص "هل يوجد أبناء" يستخدم `IQueryable != null` (يكون دائماً غير NULL حتى لو فارغاً) - **يمنع الحذف دائماً بصمت خطأً محتملاً** لو لم يُصحَّح لـ`.Any()`. (2) `Gov_City_ListCLS.Delete`: يحذف فعلياً من جدول **`Govern_List`** (المحافظات) بدل `Gov_City_List` (المدن) عند طلب حذف مدينة - **خطأ حقيقى خطير** (حذف الجدول الخطأ!). (3) شاشتَى "المدن": عنوان النافذة فى كليهما "المحافظة/المحافظات" بدل "المدينة/المدن" (نسخ-لصق). **هل تريد إصلاح هذه الأخطاء الثلاثة أثناء بناء نسخة Blazor** (بموافقتك الصريحة، كما فعلنا سابقاً مع أخطاء مشابهة)، أم تركها كما هى فى الأصل والاكتفاء بالتوثيق؟ |
| **زر معطَّل حقيقى فى `BanksFrm` الحية** | `toolStripButtonEdit_Click` ("تعديل بيانات البنك") **فارغ تماماً بلا أى تنفيذ** - يجب توثيقه، لن يُنقَل (لا وظيفة لننقلها). |

## 2) قرارات الدمج (لتفادى تكرار العمل)

| الشاشات الأصلية | القرار | لماذا |
|---|---|---|
| `FrmStaticEditSysConfig` + `Static_NotesInInvoice` | **صفحة واحدة** | نفس مفتاح الإعداد بالضبط (راجع القسم 1). |

## 3) ترتيب التنفيذ المقترح (من الأبسط/الأكثر جاهزية، إلى الأعقد)

1. **فوز سريع منخفض المخاطر (شاشات CRUD مسطَّحة جاهزة تماماً - كلاسات EF Core حديثة موجودة فعلاً فى `AccountModelsLib`)**:
   - ✅ **تم** طرق الدفع النقدى (`CashPaymentMethodCLS`) — `CashPaymentMethodList.razor` (`/main-data/cash-payment-methods`)، `SysConfigMenus.RazorPath` مربوط لصف `toolStripMenuItemCashPaymentMethod`، اختُبِرت حياً (إضافة/تعديل/حذف، تأكيد من قاعدة البيانات مباشرة بعد كل عملية، وفتح الشاشة من بطاقة القائمة الرئيسية)
   - ✅ **تم** بيانات شركات الشحن (`ShipmentCompanyEFCLS`) — `ShipmentCompanyList.razor` (`/main-data/shipment-companies`)، `SysConfigMenus.RazorPath` مربوط لصف `toolStripMenuItemShipmentCompany`، اختُبِرت حياً (إضافة/تعديل/حذف عبر الكلاس EF Core الحديث، كل عملية مؤكَّدة من قاعدة البيانات مباشرة، Id يُولَّد فعلياً عبر Snowflake هنا بخلاف البند السابق)
   - بيانات الماكينات (`Machin_listCLs`)
   - بيانات الموظفين/العاملين (`EmployeeService`)
   - رسمات التشغيل الخارجى (`DrawsServiceCls`)
   - ✅ **تم** نص بيان الفاتورة + تغيير الإعدادات (صفحة مدمجة واحدة، القسم 1) — `InvoiceNotesSettings.razor` (`/settings/invoice-notes`)، `SysConfigMenus.RazorPath` مربوط ومُشفَّر لصفَّى `toolStripMenuItemEditSysConfig`/`toolStripMenuItemInvoiceNotes`، اختُبِرت حياً فى المتصفح (تسجيل دخول Admin، فتح كِلا عنصرَى القائمة، حفظ نص وتأكيد بقائه بعد إعادة تحميل الصفحة بالكامل)
   - أنواع الكونترا (`TagerKontraCLS` - نمط SQL خام أقدم لكن بسيط جداً: عمودان فقط)

2. **شجرة المناطق الجغرافية**: بناء `CascadingLocationPicker` + `SimpleLookupList`، ثم 4 شاشات الدول/المناطق/المحافظات/المدن مبنية عليهما - **بانتظار قرارك بخصوص الأخطاء الثلاثة المكتشفة (القسم 1)** قبل البدء هنا تحديداً.

3. **مكوّن البنوك/الصناديق الموحَّد** (`BanksFrm`+`MoneyBanksFrm`+`SandoukBranch`) - أعقد قليلاً (حوارات فرعية للرصيد الافتتاحى، فروق حسب النوع)، لكن يعتمد فقط على `BanksClss` الجاهزة.

4. **فروع الشركة** (`BranchesListFrm`) - متوسطة التعقيد (جدول قابل للتحرير مباشرة + إنشاء حساب فرعى/مركز تكلفة تلقائى مرتبط عند الإضافة).

5. **بيانات المخازن والأقسام** (`Store_ListFrm`) - الأعقد فى هذه الدفعة (تبويبان، قوائم متتالية، 5 أعلام منطق عمل، ترميز عربى يحتاج حذراً خاصاً).

6. **مندوبو المبيعات**: بيانات مندوبين المبيعات (`SalesMan_Info` - يحتاج كتابة CLS جديدة، لا يوجد كلاس جاهز) ثم عملاء مندوبى المبيعات (`CustomerSalesMan` - كلاس `CustomersAccountCLS` جاهز، أبسط).

7. **شيكات أول المدة (وارد/صادر)** - مكوّن واحد بباراميتر (القسم 2)، يعتمد على محرك `FirstBalance_CLS`/`Order_Receipt_ChecksNewNew` الموجود.

**مؤجَّل/مستبعَد من هذه الدفعة بالكامل** (لا حاجة لعمل فى أى منها الآن، راجع القسم 1 للتفاصيل): طباعة كشف
العملاء/الموردين (تقارير)، بيانات حساب عميل-مورد-مختلط (ربط)، تست طباعة الباركود، إعدادات طباعة الباركود
(مصمِّم GDI+)، قيود إفتتاحية سابقة (معطَّلة أصلاً).

## 4) ما يحتاج قرارك الآن لأبدأ

1. هل توافق على الترتيب المقترح فى القسم 3؟
2. هل توافق على قرارات الدمج الثلاثة فى القسم 2؟
3. بخصوص الأخطاء الثلاثة الحقيقية المكتشفة فى شاشات الدول/المدن (القسم 1) - **أُصلِحها أثناء البناء بموافقتك الصريحة (نفس نهجنا مع أخطاء مشابهة سابقاً)، أم أتركها كما هى وأكتفى بالتوثيق فى `winforms-porting-checklist.md`؟**
4. هل توافق على استبعاد/تأجيل الشاشات الست المذكورة فى نهاية القسم 3؟

بمجرد موافقتك، سأبدأ التنفيذ بالترتيب أعلاه، دفعة تلو الأخرى، مع اختبار حى فى المتصفح لكل دفعة قبل الانتقال
للتالية - بنفس المنهجية المُتَّبعة فى دفعة "الحسابات".
