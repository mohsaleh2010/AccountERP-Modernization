## 1) الوضع الحالى

### 1.1 شاشة الإذن
- **شاشة واحدة** `Store_LIB\OrdersNew\NewLast\Order_DetailsWorkNewFrm.cs` (3759 سطراً، Windows-1256) لكل الأنواع، تُفتح بـ `new Order_DetailsWorkNewFrm((int)StoreOrderType.X)`. المحرك `Order_DetailsNewCls` (4801 سطراً).
- **بيانات كل نوع** فى جدول `DataDictionaryProcessesLists` (Id = رقم النوع 1001…1023): الاسم، الاتجاه `Order_Estlam_Sarf` (1 وارد / 2 منصرف)، نص زر الحفظ. **أطراف الإذن (من/إلى)** مبرمجة فى `FillcbOrderStorCLS` لكل نوع (مخزن، عميل، مورد، قسم، ماكينة، موظف، ورشة، إنتاج، هالك، مخزن خارجى).
- **مكونات الشاشة:**
  - الرأس: رقم الإذن بالتسلسل حسب النوع، التاريخ، من/إلى، رقم أمر الشغل للسيارات، والملاحظات.
  - حوار إضافة صنف `ItemDataStore`: يعرض الرصيد ونوع السعر (`StorePriceTypeEnum`)، والتشغيلة والصلاحية.
  - جدول الأصناف بتعديل داخلى.
  - الحفظ، والطباعة، والتنقل السابق/التالى، والبحث برقم الإذن، و«استلام بالخامات» لإذن الاستلام من الإنتاج.
- **التعديل والحذف:**
  - `Edit_OrderFromOK` و`Edit_Order_DetailsFromEdit` و`Delete_Order_DetailsFromEdit` تعدّل الرصيد بالفرق.
  - كارت الصنف القديم يفتح `Order_DetailsWorkEdit` للتعديل.
- **نسخ موازية فى نفس المجلد/المشروع:** `Order_DetailsWorkNewFrm1`، و`NewFolder1\__Order_DetailsWorkNewFrm`، و`_Order_DetailsWorkNew`، و`Order_DetailsWork`، و`Order_DetailsWorkMulti` (تغيير هوية صنف)، و`Order_DetailsWorkEdit`. **كلها تُصرَّف** (لا `Compile Remove` إلا لملفين فى `Dept_Item`). الحية من القائمة هى `Order_DetailsWorkNewFrm` و`TransferItemsWorkNew` و`Order_DetailsWorkMulti` فقط.

### 1.2 ما سبق تحويله
- `Pages/Store/ItemsMovementList.razor` (`/store/item-movement/{period|daily}/{1|2}`) يحل محل أربع شاشات «حركة المخازن / يومية المخزن» لأصناف المبيعات والمشتريات. يعتمد على `ItemsCardsCLS.Get_AllItemCardStore` (أذون فقط، لا فواتير) وللعرض فقط.

### 1.3 عناصر بلا شاشة
- «إذن صرف لقسم» و«إذن إستلام من قسم»: المعالج فارغ.
- «بحث أذونات صرف إلى موظف»: لا يوجد معالج.

## 2) التصميم المقترح

### 2.1 تعريف أنواع الأذون كبيانات
جدول إعداد جديد **`Store_Order_Type_Settings`** (أو أعمدة تُضاف على `DataDictionaryProcessesLists` — قرار §4) لكل نوع:

| الحقل | المعنى |
|---|---|
| `Order_Type` | 1001…1023 (لا تغيير فى الأرقام) |
| `Direction` | 1 وارد / 2 منصرف / 3 تحويل (منصرف من طرف + وارد لطرف) |
| `From_Party_Types` / `To_Party_Types` | أنواع الأطراف المسموحة (مخزن، سيارة مندوب، عميل، مورد، قسم، ماكينة، موظف، ورشة، إنتاج، هالك، مخزن خارجى) |
| `Price_Source` | لا سعر / المتوسط / آخر شراء / سعر يدوى (للاستلام من مورد والمرتجع) |
| `Updates_Avg_Cost` | هل الوارد يحدّث المتوسط (خطة 01 §2.3) |
| `Requires_Receipt_Confirmation` | للتحويل: هل يحتاج تأكيد استلام من الطرف المستلم |
| `Menu_Id` | ربط عنصر القائمة والصلاحية |

يُملأ بسكربت يطابق السلوك الحالى المبرمج فى `FillcbOrderStorCLS` بالضبط، ثم يصبح هو المرجع.

### 2.3 سلوك صفحة الإذن
1. **الرأس:** النوع (ثابت من المسار)، الرقم (تسلسل لكل نوع كالحالى `GetNewOrderNo`)، التاريخ، الطرف من/إلى حسب الإعداد، المخزن، أمر الشغل (اختيارى)، والملاحظات.
2. **الأصناف:**
   - الإضافة: بحث بالاسم أو الكود أو الباركود، ثم الوحدة الكبرى والصغرى والعبوات.
   - العرض بجانب السطر: الرصيد والمتاح والمحجوز للطلبيات.
   - السعر حسب `Price_Source`، والتشغيلة والصلاحية إن كان الصنف يتتبعها.
   - التحقق الفورى من كفاية الرصيد.
3. **الحفظ والترحيل:** «حفظ» يحفظ مسودة بلا أثر؛ «ترحيل» معاملة واحدة تنشئ `Order_Purshing` و`Detailes_Purshing`، ثم `StockMovementService.Post` لكل سطر (يكتب DPIE ويحدّث `Unit_item` والمتوسط).
4. **دورة المستند (قرار 2026-10-08 بعد المراجعة — المتبع حديثاً):** مسودة (تعديل/إلغاء حر بلا أثر) ← ترحيل (أثر نهائى عبر المحرك) ← **تصحيح المرحَّل بإذن عكسى مرتبط** (`Reverse`) أو «عكس ونسخ للتعديل» (`ReverseAndCopy`) بسبب وتدقيق. **لا تعديل ولا حذف لإذن مرحَّل.** يُمنع العكس إن بُنى على الإذن مستند آخر (استلام تحويل، إنتاج) قبل عكس ذلك المستند.
5. **التحويل:**
   - الإصدار يخصم من المرسل ويضع البضاعة «فى الطريق».
   - المستلم يؤكد الاستلام كلياً أو جزئياً، والفرق يُرفض أو يُسوّى بسبب.
   - **مباشر أم بتأكيد:** حسب «طريقة التحويل» العامة والصلاحية المتقدمة «تحويل مباشر بين المخازن بدون تأكيد استلام» (خطة 01 §2.7)؛ التحويل المباشر يحرك المخزنين فى نفس المعاملة.
6. **الطباعة:** نموذج الإذن عبر مرحلة التقارير المشتركة (PDF/Excel).

### 2.4 «بضاعة فى الطريق»
- حالة للإذن (لا مخزن وهمى) تُحسب من الأذون المصدرة غير المستلمة.
- تظهر فى تقرير «تحويلات بانتظار الاستلام» وفى رصيد السيارة للمندوب (خطة 06).

## 6) الاختبار (لكل نوع)
- رصيد `Unit_item` قبل/بعد للمرسل والمستلم، وصف DPIE، والمتوسط حسب الإعداد.
- رقم الإذن بالتسلسل الصحيح لنوعه.
- المسودة لا تحرك رصيداً؛ الترحيل يحرك؛ العكس يعيد الرصيد كما كان ويظهر مرتبطاً بالأصلى؛ المرحَّل يرفض التعديل والحذف.
- التحويل: لا زيادة عند المستلم قبل التأكيد (إلا مع الاستلام التلقائى).
- مقارنة كل نوع بنتيجة الشاشة القديمة على نفس البيانات.
