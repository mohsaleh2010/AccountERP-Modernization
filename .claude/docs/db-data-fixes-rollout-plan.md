# خطة تصحيحات قاعدة البيانات المطلوب تعميمها على كل القواعد الأخرى

كل تصحيح بيانات (لا كود) يُنفَّذ مباشرة على قاعدة التطوير `ClientNew` فى جدول رئيسى أو جدول Lookup يُسجَّل هنا فور تنفيذه، لأن نفس كود التطبيق (الويندوز أو Razor) الذى أنتج الخلل يعمل على بقية قواعد العملاء أيضاً. **لا يُطبَّق أى بند هنا على أى قاعدة أخرى إلا بطلب صريح من المستخدم.**

---

## 1) شجرة الحسابات: الحسابات الرئيسية مربوطة بفرع واحد بدل أن تكون مشتركة

- **الجدول:** `Submain_Account`.
- **العلة:** كل الحسابات (كل الصفوف بلا استثناء) كانت مسجَّلة بـ`Branch_Id = 1` بدل `Branch_Id = -1` (العلامة التى يفهمها الاستعلام `Get_SubMain_Account` كـ"حساب مشترك لكل الفروع"). السبب فى كود التطبيق: كل مسارات إنشاء الحساب (فى الويندوز والـRazor معاً، `Sub_Account`/`Add_Account_CodesCLS`) تختم الحساب الجديد تلقائياً بفرع الجلسة الحالية، ولا يوجد ولا كان يوجد خيار "حساب مشترك" فى أى منهما. طالما كانت الشركة تعمل بفرع واحد فقط، لم يظهر الخلل؛ ظهر فقط عند إضافة فرع ثانٍ (شجرة الحسابات تبدو فارغة تماماً لأى فرع غير الفرع الذى أُنشئت الحسابات وهو فيه). التفاصيل الكاملة والتحليل فى `accounts-tree-multibranch-plan.md`.
- **الفحص قبل التطبيق على أى قاعدة أخرى:**
  ```sql
  -- إن أعاد هذا الاستعلام صفراً، فكل حسابات هذه القاعدة مربوطة بفرع واحد فقط وتحتاج نفس التصحيح
  -- (فقط إذا كانت القاعدة تستخدم أكثر من فرع فعلاً، أو تنوي ذلك مستقبلاً)
  SELECT COUNT(*) FROM Submain_Account WHERE Branch_Id = -1;
  SELECT DISTINCT Branch_Id FROM Submain_Account;
  ```
- **الاستثناء الذى يجب فحصه واستبعاده قبل التنفيذ فى أى قاعدة أخرى:** أى صف يمثِّل حساب/صندوق فرع بعينه (البصمة: `Account_Customer_Type_Value = 0` كما تُنشئه `AccountBranchesCLS.AddBranch`) يجب أن **يبقى** مربوطاً بفرعه، ولا يُحوَّل لمشترك:
  ```sql
  SELECT Id, SubAccount_Name, Branch_Id FROM Submain_Account WHERE Account_Customer_Type_Value = 0;
  ```
- **العبارة المنفَّذة على `ClientNew`** (بعد التأكد أنه لا يوجد استثناء، 2026-09-27):
  ```sql
  UPDATE Submain_Account SET Branch_Id = -1 WHERE Id > 0;
  ```
  فى قاعدة أخرى بها استثناءات فعلية، تُعدَّل الجملة لتستثنيها: `... WHERE Id > 0 AND Account_Customer_Type_Value <> 0` (أو حسب ما يظهره الفحص أعلاه من صفوف فرعية حقيقية).
- **متطلَّب مصاحب فى الكود** (منفصل عن تصحيح البيانات، راجع `accounts-tree-multibranch-plan.md` القسم 4): تعديل شاشة «إضافة حساب» (Razor والويندوز) ليكون الافتراضى عند إضافة حساب جديد هو `Branch_Id = -1`، مع خيار صريح لمن يريد حساباً خاصاً بفرعه فقط — بدون هذا التعديل، أى حساب جديد بعد هذا التصحيح سيعود ليُنشأ مربوطاً بفرع واحد من جديد.
