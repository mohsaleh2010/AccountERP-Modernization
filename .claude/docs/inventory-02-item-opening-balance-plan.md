# خطة 02 — رصيد أول المدة للأصناف

تاريخ الإعداد: 2026-10-08. **الحالة: القرارات معتمدة؛ المراحل 1-2 طُبِّقت والخدمة (المرحلة 3) بُنيت واختُبرت 2026-10-09 — الشاشة والإقفال متبقيان.** الأولوية 2 فى [خريطة الطريق](inventory-00-roadmap.md). هذه الخطة هى **المرحلة 5** المؤجلة فى [`opening-balances-master-plan.md`](opening-balances-master-plan.md) وتحل محلها.

**الهدف:** لكل فترة مالية رصيد أول مدة لكل (صنف × مخزن) بكمية **وتكلفة**، يكون نقطة البداية لـ «الرصيد = أول المدة + الحركات» (خطة 01)، ويُدخَل بشاشة Razor واحدة بثلاث طرق: يدوى، استيراد، ونقل آلى من رصيد آخر الفترة السابقة.

## 2) التصميم المقترح

### 2.1 الجدول
**الخيار المقترح (أ): إضافة أعمدة لـ `Item_First_Period_Balance` القائم** (لا إعادة تسمية):
| العمود | الغرض |
|---|---|
| `Year_Financial_Period_Id` | الفترة المالية (نفس مفهوم بقية أرصدة أول المدة) |
| `Store_Id` | المخزن صراحةً (اليوم يُستنتج من `Unit_Item_Id` فقط) |
| `Unit_Cost` | تكلفة الوحدة الصغرى لأول المدة (تغذّى المتوسط) |
| `Source` | يدوى / استيراد / نقل من الفترة السابقة |

مع **قيد فريد** (`Year_Financial_Period_Id`, `Unit_Item_Id`) يمنع التكرار.
**البديل (ب):** جدول جديد `Item_Period_Opening_Balance` وترك القديم للقراءة — أنظف لكن يضيف جدولاً.

### 2.2 تنظيف البيانات الحالية (قبل الأعمدة الجديدة، وبموافقة، لكل قاعدة عميل)
1. نسخة احتياطية من الجدول.
2. حذف الأيتام (سطر مخزون محذوف) — 2416 فى قاعدة التطوير.
3. دمج التكرار: يبقى أحدث صف لكل سطر مخزون.
4. ربط كل صف بفترته المالية من `Balance_Date`.
5. تقرير قبل/بعد لكل خطوة.

### 2.3 الربط مع الرصيد الجارى والحركة
- رصيد أول المدة **صف افتتاحى فى الدفتر**: عند اعتماد أول مدة لفترة يُكتب صف DPIE من نوع «رصيد أول المدة» عبر محرك خطة 01، فيصبح الحساب `أول المدة + الحركات` متسقاً، ويُضبط `Unit_item` (الكمية) و**متوسط (صنف × فرع)** فى `Item_Branch_Cost` من `Unit_Cost` فى نفس المعاملة.
- **تعديل أول المدة بعد وجود حركات** = مستند عكسى للصف الافتتاحى ثم ترحيل جديد (دورة مسودة ← ترحيل ← عكس، خطة 01 م-01-8)، فيتعدل الرصيد الجارى بالفرق تلقائياً. لا تعديل صامت.
- **نقل آلى للفترة التالية:** رصيد آخر الفترة المحسوب (خطة 01 §2.2) ← أول مدة الفترة الجديدة بنفس التكلفة (المتوسط). هذا هو الإقفال المخزنى السنوى.

### 2.4 الشاشة (Razor) «رصيد أول المدة للأصناف»
- فلاتر: الفترة، المخزن، الفئة/المجموعة، بحث الصنف.
- جدول قابل للتحرير: الصنف، الوحدة الكبرى/الصغرى/العبوات، تكلفة الوحدة، القيمة، المصدر.
- إجراءات: حفظ، **استيراد Excel** (قالب)، «نقل من الفترة السابقة»، «تصفير»، وعرض «الرصيد الجارى الآن» بجانب أول المدة للمقارنة.
- الصلاحية: عنصر قائمة جديد بصلاحية خاصة؛ الفترة المقفلة للقراءة فقط.

### 2.5 المحاسبة
- مع الجرد الدورى (قرار م-01-1): **لا قيد**؛ إجمالى قيمة أول المدة لكل نوع مخزن يُعرض كمرجع لمطابقة `Financial_Period_Stores_Balance` (أول المدة) ويُنبَّه عند الاختلاف.
- عند التحول للجرد المستمر (محركه يُبنى مع خطة 01 ويُفعَّل بتاريخ): قيد افتتاحى واحد (من المخزون إلى الرصيد الافتتاحى 64) بنفس آلية `BalanceOpeningBalanceEquity` المستعملة فى الحسابات.

## 6) الاختبار
- إدخال أول مدة لصنف ← `Unit_item` = الكمية، المتوسط = التكلفة، صف DPIE افتتاحى.
- تعديله بعد بيع ← الرصيد الجارى يتعدل بالفرق فقط.
- النقل للفترة التالية ← أول المدة الجديد = آخر القديم المحسوب، والمطابقة صفر فروق.
