# Forms Inventory & Screen Navigation

The full per-project, per-screen catalog — every WinForms form's purpose, key operations, navigation targets, DB tables/procs, and per-project "batch observations" (duplication, dead code, encoding issues, etc.) — plus the complete screen-navigation map, live in **[`FORMS_INVENTORY.md`](../FORMS_INVENTORY.md)** at the solution root rather than in this file, to keep this document focused and short.

Headline facts worth keeping here:

- **≈712 forms found via a naive `class X : Form` scan across 34 WinForms-bearing projects** — but this is a **lower bound**. Several projects route the majority of their real screens through custom intermediate base classes that a naive scan misses: `Project_ControlLIB.MyForm` (used across `Connection4It`, `Account_Common_LIB`, `CarsSystemLib`, `General_Ledger`, `ConstructionLib`, and `Advanced_Account`'s `MainFrm_AccountUpdate`), `Connection4It.Template_Frm`, and DevExpress's `XtraForm` (used throughout `EASY E-INVOICE`, almost entirely undercounted). Where re-verified, corrected totals are noted in `FORMS_INVENTORY.md` (e.g. `General_Ledger` 58, `ProductionsRates` 49, `ConstructionLib` 30 — all higher than the naive count; `CarsSystemLib` has ~48 additional `MyForm`-based forms never individually catalogued).
- **The solution has no single navigation tree — several independent MDI hubs**, one per deployable EXE. The real main menu of the main ERP app is **`MainFrm_AccountUpdate`** — confirmed (via direct `.csproj` `ProjectReference` inspection) to live in the **`Accounts`** project (`Accounts\AccountMainFrm\MainFrm_AccountUpdate.cs` + `.Designer.cs`, ~15,300 lines combined), **not** `Advanced_Account` as earlier passes assumed — `Advanced_Account` holds its own disconnected duplicate that is never compiled into either EXE shell. This is not either EXE shell's nominal startup form. The full extracted menu→screen map (620 menu-item fields, 477 leaf actions resolved to their target form via `Name`/`Click`) is at [`../.claude/docs/main-menu-screen-map.md`](../.claude/docs/main-menu-screen-map.md). `MainFrmPOS` (`Accounts` project) is the separate POS/restaurant MDI hub. Standalone tools (`Alter_DataBase`, `Stores`, `BarCodeCreator`, `GHospital_Care`, `Clinic`/`ClinicPatient`, `FreeMedical`, `EASY E-INVOICE`, `DataBaseSettining`, `EncryptionCA`, `administration`) each have their own independent MDI hub, not reachable from the main ERP app.
- **Permission-gated dynamic dispatch is real and load-bearing**: `PERMATIONS`/`FORMS_DETAILES`/`SysConfigMenusPERMATIONS`-family tables gate which menu items a user sees, and several forms with no `new X()` call found anywhere in their own project are very likely instantiated by reflection using a form name stored in one of those tables (observed in `Stores`, `CarsSystemLib`, consistent with `Alter_DataBase`'s permission architecture). See [Areas Requiring Further Investigation](investigations.md).

For anything more specific than the above — an individual screen's fields, its exact DB tables, what it navigates to — **open `FORMS_INVENTORY.md`**, do not guess or re-derive it from this summary.
